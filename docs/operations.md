# Эксплуатация

## Хранилища и каталог

Backend использует PostgreSQL `banger_game` для комнат и каталога. LLM использует
PostgreSQL `banger_llm` для заданий. Оба сервиса используют приватный S3-бакет
для загруженных и сгенерированных изображений.

На пустой БД сначала применяются миграции, затем загружается каталог. Начальные
данные лежат в `services/backend/src/game/catalog_seed.json`. Инициализация
добавляет недостающие записи и сохраняет существующие значения. Для явного
обновления каталога используйте `python scripts/seed.py` с доступом к БД backend
через `DATABASE_URL`. После обновления перезапустите backend, чтобы он перечитал каталог.

## Провайдер изображений

Локально и в `test` используется `fake`. В `prod` выбран `polza`, для него нужен
секрет `POLZA_API_KEY`. Привязку ключа нужно заполнить перед запуском prod.

Динамический конфиг `image-generation` задаёт `provider`, HTTPS-адрес
`base_url` и `model` для новых заданий. Для отправленных заданий сохраняются
исходные параметры. Токен отправляется на доверенный HTTPS origin,
который можно задать через `POLZA_API_ORIGIN`.

## Диагностика

- `GET /api/health` проверяет доступность публичного API.
- `/healthz` и `/readyz` доступны на внутренних HTTP-портах компонентов.
- Trace ID связывает запрос backend, задание LLM и операции с S3.
  Логи, метрики и трассы доступны в настроенной observability.
- Проверки игрового домена, каталога и провайдеров запускаются командой
  `python scripts/test.py`.

Окружения `test` и `prod` сейчас выключены в `deploy.yaml`. Домен в
`ingress.yaml` для prod задан как пример.
