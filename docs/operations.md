# Эксплуатация

## Хранилища и каталог

Backend использует PostgreSQL `banger_game` для комнат, каталога и очереди заданий.
Загруженные и сгенерированные изображения хранятся в приватном S3-бакете Banger.

На пустой БД сначала применяются миграции, затем загружается каталог. Начальные
данные лежат в `services/backend/src/game/catalog_seed.json`. Инициализация
добавляет недостающие записи и сохраняет существующие значения. Для явного
обновления каталога используйте `python scripts/seed.py` с доступом к БД backend
через `DATABASE_URL`. После обновления перезапустите backend, чтобы он перечитал каталог.

## AI Gateway

Локальный запуск и тесты используют встроенный мок AI Gateway. Для prod
укажите ссылки на `AI_GATEWAY_URL` и `AI_GATEWAY_TOKEN` в
`environments/prod.yaml` у backend. URL должен вести на приватный маршрут
активного Gateway в Platform. Для токена выдайте приложению доступ к нужной
модели в Gateway.

Динамический конфиг backend `image-generation` задаёт идентификатор модели.
По умолчанию используется `polza-ai-grok-imagine`. Воркер сохраняет выбранную
модель на первой отправке задания и повторяет запрос с тем же значением.

## Диагностика

- `GET /api/health` проверяет доступность публичного API.
- `/healthz` и `/readyz` доступны на внутренних HTTP-портах компонентов.
- Trace ID связывает запрос backend, задание Gateway и операции с S3.
  Логи, метрики и трассы доступны в настроенной observability.
- Проверки игрового домена, каталога и клиента Gateway запускаются командой
  `python scripts/test.py`.
