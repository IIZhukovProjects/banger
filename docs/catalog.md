# Игровой каталог в PostgreSQL

Режимы, задания и подписи способностей хранятся в БД backend:

- game_modes — название, описание, тип, поля ответа, порядок меню и mix;
- game_prompts — задания режима, контекст, twists/scene и другие данные раунда;
- game_powers — отображаемые названия, описания и иконки реализованных способностей.

Схему создаёт миграция `0003_catalog`. В `service.yaml` объявлен
`initialize.command: [python, -m, seed_catalog]`. При `codegen run` кодген
однократно запускает его после миграций и перед стартом сервисов. Команда берёт
каталог из `services/backend/src/game/catalog_seed.json`, который входит в образ.
Она атомарно добавляет недостающие записи и сохраняет существующие значения.

Для явного обновления каталога используйте `python scripts/seed.py`.
Скрипт выполняет upsert по ID и сохраняет дополнительные записи.
Исходный набор содержит 16 режимов, 118 заданий и 5 способностей.

Можно указать --file /path/to/catalog.json и --environment prod. DATABASE_URL берется
из backend-привязки environments/ или ENV, пароль не передается аргументом командной
строки. Для платформы миграцию и скрипт нужно выполнить в runtime окружении с доступом
к предоставленной PostgreSQL и DATABASE_URL. Скрипт проверяет codegen.lock.yaml.

Backend загружает согласованный снимок БД при старте и передает его игровому домену.
После изменения каталога перезапустите backend. При запуске backend отдельно от `codegen run` инициализацию нужно выполнить заранее.
Коды способностей связаны с бизнес-правилами и остаются стабильными; текст берется из БД.

Проверены повторное заполнение, чтение измененного значения из БД, сохранение своих
записей, откат всего импорта при ошибке, отказ на пустой БД. Интеграционный тест удаляет
seed-файл после заполнения и проверяет игру, рестарт и observability без него.
